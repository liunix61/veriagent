## 4. Policy 引擎规则（Vault 核心）

按序校验，任一失败即拒绝（返回 reason 便于 Agent 自修正）：

1. **白名单**：`trade.asset ∈ policy.assetWhitelist`
2. **仓位上限**：`postTradeValue(asset) / totalValue ≤ maxPositionPct`
3. **日亏损熔断**：`dailyRealizedLoss + unrealizedDrawdown ≤ dailyLossLimitBps`
4. **冷却期**：`block.timestamp - lastTradeAt ≥ tradeCooldown`
5. **频率限制**：`tradesToday < maxTradesPerDay`
6. **暂停状态**：`!paused`

## 5. Agent 决策 Schema（LLM 输出约束）

```json
{
  "action": "BUY | SELL | HOLD",
  "asset": "0x...",            // 必须在白名单
  "amountPct": 5,              // 总资产百分比, ≤ maxPositionPct
  "reason": "三句话以内决策理由",
  "dataSources": ["cmc:NVDA", "mcp:depth:NVDA/USDC"],
  "confidence": 0.72
}
```

- Pydantic 校验，不合法直接重试（最多 2 次）→ HOLD 兜底
- `reason` + `dataSources` + prompt 版本 → keccak 后进 DecisionRecorder

## 6. x402 集成细节

```
engine → GET https://data.provider/api/v1/sig?symbol=NVDA
      ← 402 Payment Required { x402Payload }
engine → POST /pay { signedPayload }   // PaymentRouter 或 facilitator
      ← 200 { data, paymentProof }
data + paymentProof → 计入 dataSourceHash
```

- W2 先接 mock facilitator（本地），接口严格对齐 x402 规范（v2）
- 优先目标：CMC Agent Hub（Binance 生态验证过的 b402 调用模式）

## 7. 测试策略

| 层 | 工具 | 覆盖目标 |
|----|------|---------|
| 合约单元 | forge test | 100% 函数覆盖 + policy 各拒绝路径 |
| 合约模糊 | forge fuzz | policy 边界值（bps/时间/金额） |
| 合约攻击 | forge + 手写 PoC | 重入/权限绕过/session key 越权 |
| 引擎 | pytest | 决策 schema/retry/风控兜底 |
| E2E | anvil + 脚本 | 存款→决策→凭证→交易→验证全链路 |

## 8. Gas 预算（关键路径）

| 操作 | 预估 gas | 说明 |
|------|---------|------|
| record() | ~80k | 4×bytes32 + 事件 |
| executeTrade() | ~120k | policy 校验 + transfer |
| deposit() | ~70k | ERC20 transferFrom |
| bindTx() | ~45k | 单存储写 |

L2 上合计 <$0.05/循环，符合"高频小额决策"的成本要求。
