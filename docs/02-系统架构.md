## 2. 合约层详细设计

### 2.1 AgentIdentityRegistry（身份与信誉）

```
AgentRecord {
    agentId (uint256, 自增)
    owner (address)           // 控制人，可轮换 session key
    ensName (string)          // 如 "veri-001.eth" (可选)
    metadataHash (bytes32)    // 策略描述/模型版本的 IPFS hash
    registeredAt (uint64)
    reputation (int256)       // 信誉分: 成功审计+分, 违规-分
    active (bool)
}
```

- ERC-8004 风格：链上身份 + 信誉注册表（对齐 2026-01 以太坊主网标准）
- `registerAgent()` / `rotateSessionKey()` / `slashReputation()`

### 2.2 VeriAgentVault（策略金库，核心合约）

```
VaultPolicy {
    assetWhitelist (address[])  // 仅允许交易的 token (bStocks)
    maxPositionPct (uint16)     // 单资产仓位上限 (基点, 1000=10%)
    dailyLossLimitBps (uint16)  // 日亏损熔断 (基点)
    tradeCooldown (uint32)      // 两笔交易最小间隔(秒)
    maxTradesPerDay (uint16)
}

关键函数:
- deposit()/withdraw()          // 用户资金进出 (仅 owner)
- executeTrade(agentId, trade)  // 仅该 vault 绑定 agent 的 session key
- checkPolicy(trade) → bool     // 全部约束硬编码校验
- emergencyPause()              // 用户一键冻结
```

**安全设计**：
- Agent 永远拿不到资金托管权，只有"提议执行"入口且被 policy 过滤
- policy 只能由 vault owner（用户）修改，且有 timelock 防误操作
- 日亏损基于预言机价格快照计算，Agent 无法操纵

### 2.3 DecisionRecorder（决策凭证，创新核心）

```
DecisionRecord {
    decisionId (uint256)
    agentId (uint256)
    vaultAddr (address)
    actionHash (bytes32)      // keccak(动作JSON: 买卖/数量/标的)
    reasonHash (bytes32)      // keccak(LLM理由摘要)
    dataSourceHash (bytes32)  // keccak(数据源列表+x402凭证)
    modelHash (bytes32)       // keccak(模型/提示词版本)
    timestamp (uint64)
    txHash (bytes32)          // 执行交易hash (回填)
}
```

- 双阶段：`record()`（决策时）→ `bindTx()`（执行后回填交易 hash）
- 验证函数：`verifyTrade(txHash) → DecisionRecord` 供 Explorer 和第三方调用
- 链下存完整 JSON（IPFS/Arweave），链上只存 hash——省 gas 且保留可验证性

### 2.4 PaymentRouter（x402 结算）

- Agent 调用付费数据服务 → 服务返回 HTTP 402 + payload
- Agent 引擎签名 → PaymentRouter 验证并以 USDC 结算 → 服务放行数据
- 数据源凭证 hash 计入 DecisionRecord.dataSourceHash——付费记录本身成为审计证据

## 3. Agent 引擎详细设计（复用 HOODflow）

```
感知 (Perceive)          决策 (Decide)         记录 (Record)        执行 (Execute)
─────────────           ───────────          ───────────         ─────────────
robinhood-evm-mcp       LLM 推理             keccak(JSON)        viem/web3.py
16 工具拉取:             输入: 行情+持仓       DecisionRecorder    Session Key
- 实时价格              +策略约束             .record()           签名交易
- 流动性深度            输出: 结构化          ↓                   Vault
- 历史K线               decision JSON        上链成功后           .executeTrade()
x402 补充数据                                    ↓                   ↓
(CMC/投研)              ↓                   回填 txHash        链下风控
                        risk_manager.py                              二次校验
                        硬校验兜底
```

- **感知**：HOODflow MCP Client 原样复用；x402 数据为增强输入
- **决策**：LLM 输出必须通过 JSON Schema 校验（action/amount/asset/reason/sources）
- **记录**：先上链凭证再执行交易——顺序保证"决策先于动作"
- **执行**：Session Key 仅对本 vault 有效，policy 在合约层再过滤一次

## 4. 数据流与信任边界

| 边界 | 信任假设 | 保障机制 |
|------|---------|---------|
| Agent ↔ Vault | Agent 不可信 | policy 合约硬约束 + session key 限额 |
| Agent ↔ 数据源 | 数据源不可信 | 多源交叉 + dataSourceHash 留痕 |
| 用户 ↔ Vault | 用户完全控制 | owner-only 管理 + emergencyPause |
| 第三方 ↔ 审计 | 无需信任任何人 | 链上凭证自验证 |
