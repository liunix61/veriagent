# VeriAgent 核心流程（Core Flows）

> 创建：2026-09-13 | 配套文档：01-总体方案 / 02-系统架构 / 03-技术框架

---

## 流程 1：Agent 注册与身份建立

```
开发者                AgentIdentityRegistry              链下
   │                        │                             │
   │ 1. 策略/模型描述 ──────→│                             │──→ IPFS (metadata全文)
   │ 2. registerAgent(hash) │                             │
   │←────── agentId ────────│                             │
   │ 3. 绑定 session key    │                             │
   │    (rotateSessionKey)  │                             │
```

- 一个 agentId = 一份可验证的"策略说明书"（metadataHash 指向模型/prompt/策略版本）
- ENS 名字可选绑定（`veri-001.eth`），供人类识别
- 信誉分从 0 开始：成功交易且审计通过 +1，违规被熔断 -5

## 流程 2：用户创建 Vault（金库）

```
用户                  VeriAgentVault                 Agent
 │ 1. createVault(agentId, policy)  │                  │
 │    (白名单/仓位上限/日亏损/冷却)  │                  │
 │ 2. deposit(USDC) ───────────────→│                  │
 │ 3. 授权 session key ─────────────│←─ 绑定 ──────────│
```

- policy 一经设定进入 **timelock（24h）** 后才生效——防用户误设也防社工
- 用户随时 `emergencyPause()`，Agent 立即失效
- Vault 之间完全隔离：一个 Agent 可服务多个 Vault，但权限不互通

## 流程 3：核心交易循环（最重要）

```
Agent引擎                    链下服务                合约层
────────                    ────────               ──────
T0 感知: mcp行情 + x402付费数据
T1 决策: LLM → decision JSON (schema校验)
        ↓ 失败重试≤2次 → HOLD兜底
T2 链下风控: risk_manager 校验
        ↓ 通过
T3 记录: record(actionHash, reasonHash,
        dataSourceHash, modelHash)
        ──────────────────────────→ DecisionRecorder.record()
        ←────── decisionId ────────
T4 执行: session key 签名
        ──────────────────────────→ Vault.executeTrade(trade)
                                     │ checkPolicy() 6项校验
                                     │  ├─ 通过 → transfer + 事件
                                     │  └─ 拒绝 → revert(reason)
T5 回填: bindTx(decisionId, txHash)
        ──────────────────────────→ DecisionRecorder.bindTx()
T6 休眠 tradeCooldown → 回到 T0
```

**关键设计**：凭证先于交易（T3 < T4），杜绝"先斩后奏"；policy 合约层二次校验，链下风控失效也不怕。

## 流程 4：x402 付费数据购买

```
Agent ──GET /api/signal──→ 数据服务
     ←──402 + x402Payload──
Agent ──签名+结算(USDC)──→ PaymentRouter/托管方
     ←──200 + data + proof──
data + proof → 汇入 dataSourceHash → 进入流程3的T3
```

- 每一笔付费数据都有链上痕迹——审计时可以追问"你当时看了什么数据、花了多少钱"
- 无付费需求的循环自动跳过（感知层 mcp 数据免费）

## 流程 5：第三方审计验证（Audit Explorer）

```
验证者输入 txHash
   → Explorer 调 verifyTrade(txHash)
   → 返回 DecisionRecord {agentId, actionHash, reasonHash, ...}
   → IPFS 取回决策全文 JSON
   → 本地重算 keccak(JSON) == reasonHash ? ✅ 决策未被篡改
   → 核对: txHash ↔ decisionId ↔ agentId ↔ vault 一致性
   → 展示: Agent身份/信誉分/该Agent历史违规记录
```

**卖点**：验证全程不需要信任 VeriAgent 团队任何人——纯链上+IPFS 自证。

## 流程 6：违规与熔断场景

| 场景 | 检测方 | 处置 |
|------|--------|------|
| Agent 下单超出白名单 | Vault.checkPolicy | revert，交易不成立 |
| 日亏损达限额 | Vault.checkPolicy | 当日全部交易 revert + 事件告警 |
| LLM 输出非法 | 引擎 schema 校验 | 重试→HOLD，不上链 |
| 紧急情况 | 用户 | emergencyPause 全冻结 |
| 恶意 session key | owner 轮换 + 限额 | 旧 key 即时失效 |

## 异常分支汇总

| 异常 | 处理 |
|------|------|
| LLM 超时/输出非法 | 重试 2 次 → HOLD → 记录"未决策"事件 |
| x402 服务不可用 | 降级为纯 mcp 数据继续，dataSourceHash 标记降级 |
| record 成功但 execute 失败 | 凭证保留为"已决策未执行"，诚实可查 |
| RPC 挂 | 引擎指数退避，冷却期机制天然限速 |
